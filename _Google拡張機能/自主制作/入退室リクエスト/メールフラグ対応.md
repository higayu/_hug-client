# 入退室リクエスト拡張 — メール・本番委譲

**バージョン:** 1.4.0  
**対象:** HUG 出席表（`attendance.php?mode=detail`）上の拡張パネル

---

## 概要（v1.2.0）

| `is_mail` | 拡張パネルの動作 |
|-----------|------------------|
| **0** | 拡張が `ajax_attendance.php` へ簡易 POST（`mail_flg: 0`） |
| **1** | **本番の入室/退室ボタンをクリック**し、メール・30分未満・算定区分など **本番フロー全体**に委譲 |

メールが必要な児童では、拡張独自のメールダイアログは使わず、本番 `#addtend_dialog_mail` 等をそのまま利用します。

---

## 用語

| 名前 | 意味 |
|------|------|
| `is_mail` | 児童設定。「メール確認を本番で行うか」 |
| `mail_flg` | POST 時の実際の通知有無（本番ダイアログで決定） |

---

## 処理フロー

### `is_mail === 1`（本番委譲）

```
入室（本番） / 退室（本番）クリック
  → #enter{r_id} / #leave{r_id} 内の本番ボタンを .click()
  → sendEnterMail / sendLeaveMail（本番 attendance.js）
  → メール・算定・30分未満など本番ダイアログ
  → 完了後、パネル「更新」で一覧反映
```

### `is_mail === 0`（拡張 POST）

```
入室記録 / 退室記録クリック
  → nyushitu / taishitsuFromOnclick（mail_flg: 0）
  → runAttendanceUpdate()
```

## API（`window.HugAttendance`）

| API | 説明 |
|-----|------|
| `shouldDelegateEnterToNative(item)` | メールあり & 本番入室ボタンあり |
| `shouldDelegateLeaveToNative(item)` | メールあり & 本番退室ボタンあり |
| `triggerNativeEnter(item)` / `triggerNativeLeave(item)` | 本番ボタン click |
| `isEnterMailEnabled` / `isLeaveMailEnabled` | `is_mail` 判定 |
| `NATIVE_STATUS_ENTER` / `NATIVE_STATUS_LEAVE` | パネルステータス文言 |

---

## 動作確認

1. 拡張を再読み込み（v1.2.0）
2. `is_mail=1` の行 → ボタンが **退室（本番）** 等になる
3. クリック → 本番の退室フローが動く（GET・算定・メール）
4. `is_mail=0` の行 → **退室記録** → 拡張 POST のみ

---

## 制限事項

- 出席表詳細ページで、本番ボタンが DOM にあること
- 本番委譲後は自動 `runAttendanceUpdate` しない（ダイアログ完了後に手動「更新」）
- `is_mail=0` の退室は引き続き簡易 POST（Phase 2: GET 同期などは未実装）

---

## 入室 is_mail=1 の検出（v1.3+）

- 一覧取得時に `sendEnterMail(..., 1, ...)` の行を検出（`enter-mail-export.js`）
- パネル: 件数バッジ（`入室is_mail=1: N件`）のみ。実行は各行の **入室（本番）**
- 行ボタン **入室（本番）** → `performEnterAction` → 本番 `#addtend_dialog_mail`（通知する/しない）
- ~~JSON 自動ダウンロード~~ → **停止**（v1.4.1 以降）

## API 追加（v1.4.0）

| API | 説明 |
|-----|------|
| `performEnterAction(item)` | 本番委譲 → 拡張メール+POST → 通常POST の順で入室 |
