# 児童データ取得テスト — 全件取得と抽出取得の違い

HUG WM の「サービス提供記録・ケア記録・生活記録」（`contact_book.php`）から児童一覧を取得する拡張機能の整理。

## 結論（どちらを使うか）

| 目的 | 使うファイル | 取得元 |
|------|-------------|--------|
| URL の条件（日付範囲など）に合う児童だけ欲しい | **content.js**（manifest 既定） | 一覧テーブル |
| 施設に紐づく児童マスタを全部欲しい | **content_all.js** | `#name_list` |

---

## 背景：なぜ `#name_list` だけでは足りないか

初期実装では `fetch` した HTML から `#name_list` の `<option>` を読んでいた。

```html
<select id="name_list" class="js_filter_children_name">…</select>
```

この select には **サーバーが返す「施設まわりの全児童」** が最初から埋め込まれている。  
`date` / `date_end` / `id` などを URL に付けても、**この HTML 部分は絞り込まれない**。

画面上で児童プルダウンが少なく見えるのは、別 JS（`child_agreement_filter.js`）が AJAX で差し替えているため。  
`fetch` + `DOMParser` ではその AJAX は動かないので、**常に全件に近いリスト** になる。

一方、**一覧テーブル**（`data-api-url="contact_book.php"` の table）は、URL パラメータに応じてサーバー側で行が絞り込まれる。  
パラメータ条件に合わせた児童を得るには、こちらを読む必要がある。

---

## ⑴ 抽出取得（パラメータ一致）— `content.js`

### やっていること

1. `contact_book.php` を開いているときは **現在の `location.search` をそのまま** 一覧 URL に使う
2. 同じ条件で HTML を `fetch`（`credentials: "include"`）
3. 一覧テーブルの各行から `c_id` と児童名を抽出
4. ページネーションがある場合は **全ページ** を走査して `child_id` で重複除去

### 主な URL パラメータ（個人記録一覧と同系）

例:

```
https://www.hug-ayumu.link/hug/wm/contact_book.php?f_id=3&date=2025-06-04&date_end=2026-06-04
```

| パラメータ | 意味 |
|-----------|------|
| `f_id` | 施設 ID（画面の施設チェックなどと連動） |
| `date` | 期間の開始日 |
| `date_end` | 期間の終了日 |
| `id` | 児童 ID でさらに絞る（指定時） |
| `page` | 一覧のページ番号（スクリプトが自動で全ページ取得） |

### 抽出ロジック

- セレクタ: `table.table.lh1_5[data-api-url="contact_book.php"][data-concurrent-edit-target="ContactBook"]`
- 児童 ID: 編集ボタンの `onclick` 内 `c_id=数字`（なければプレビューリンクの `c_id`）
- 児童名: テーブル 2 列目（末尾の「さん」は除去）

### 返却イメージ（コンソール）

```js
[
  { child_id: 669, name: "赤城　壮亮" },
  { child_id: 617, name: "采岡　奏多朗" },
  // … 期間内に一覧行がある児童のみ
]
```

### 注意

- **一覧に 1 行でも出ている児童**だけが対象（期間内にレコードが無い児童は含まれない）
- ログインセッションが必要（未ログイン時はテーブルが取れずエラー）
- `contact_book.php` 以外の WM ページから実行した場合は、`content.js` 内のフォールバック URL（テスト用固定値）を使う

## ⑵ 全件取得 — `content_all.js`

### やっていること

1. `contact_book.php?f_id=3` など **最小限の URL** で HTML を取得
2. `#name_list` の全 `<option>` から `child_id` / `name` を列挙（`value="0"` の `---` は除外）

### 返却イメージ

```js
[
  { child_id: 73, name: "マイページ表示確認用" },
  { child_id: 669, name: "赤城　壮亮" },
  // … 施設まわりの登録児童が大量に並ぶ
]
```

### 向いている用途

- 児童マスタの洗い出し
- `f_id` だけ変えて「その施設に紐づく候補」を見たいとき
- 日付範囲は関係なく、ドロップダウン相当の全候補が欲しいとき

### 注意

- URL の `date` / `date_end` を付けても **#name_list の件数はほぼ変わらない**（サーバー埋め込みのため）
- ブラウザ上で AJAX 後のプルダウン件数と **一致しない** ことがある

---

## 比較まとめ

| 項目 | 抽出取得（content.js） | 全件取得（content_all.js） |
|------|------------------------|---------------------------|
| データ源 | 一覧テーブルの行 | `#name_list` の option |
| URL パラメータの反映 | される（日付・児童 id など） | されない（児童リスト部分） |
| 件数 | 少ない（条件に合う分のみ） | 多い（登録児童ほぼ全部） |
| 同一児童の重複 | 複数日の行があっても 1 件にまとめる | option 1 行 = 1 児童 |
| manifest の切替 | 既定: `content.js` | `js` を `content_all.js` に変更 |

---

## 拡張機能の切り替え

`manifest.json` の `content_scripts` → `js`:

```json
"js": ["content.js"]
```

全件テスト時のみ:

```json
"js": ["content_all.js"]
```

変更後は `chrome://extensions` で拡張を再読み込みする。
