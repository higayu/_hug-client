# 入室・退室ボタンまわりの「メールフラグ」1 と 0 の違い

対象: 保存済み出席表 HTML（`2026年05月16日…html`）および同ページで読み込まれる `attendance.js` の挙動。  
フロントで扱うフラグは実際には **2種類** あり、混同しないようにします。

---

## 用語の整理

| 名前 | 主な出所 | 意味（フロント側） |
|------|-----------|-------------------|
| **`is_mail`** | 入室: `sendEnterMail(r_id, **is_mail**, …)` の第2引数<br>退室: `sendLeaveMail(r_id, **is_mail**, …)`、および画面下部の `#leave_mail_{r_id}`（非表示） | **「保護者通知の確認ダイアログを出すか」** の設定。児童・予約・施設の設定由来（サーバが HTML に埋め込む）。`'1'`（文字列）で「ダイアログあり」判定。 |
| **`mail_flg`** | `AttendanceSave` に渡す `data_list.mail_flg`（POST 本文） | **「今回の保存で保護者へ通知メールを送るか」** の実効フラグ。サーバ側がメール送信有無に利用すると解釈できる。 |

この HTML スナップショットでは `sendEnterMail(…, 0, …)` や `#leave_mail_*` が **すべて 0** の例になっている（通知ダイアログは出ない想定）。

---

## `is_mail` が **0** のとき（通知オフ設定）

### 入室ボタン

- **即座に** `AttendanceSave` が呼ばれる。
- `data_list.mail_flg` は **常に `0`** で送られる（コード上固定）。
- **「保護者様に通知をしてもよろしいですか?」**（`#addtend_dialog_mail`）は **表示されない**。

### 退室ボタン

- 利用時間・提供形態・延長支援などの分岐の末、退室データがそろうと **そのまま** `AttendanceSave` が呼ばれる（`is_mail == 1` の経路を通らない）。
- `setAttendanceSaveData` が組み立てる `data_list` に **`mail_flg` をセットしていない**ケースがあり、その場合はサーバ側のデフォルト（多くは「送らない」相当）に委ねる。いずれにせよ **通知確認ダイアログは出ない**。

### ユーザー体感

- クリック（と中間ダイ亜ログがあればそれ）だけで記録が進み、**通知の選択は挟まない**。

---

## `is_mail` が **1** のとき（通知オン設定）

※コードは `is_mail == '1'`（文字列）と `is_mail == 1`（数値）の両方で分岐があり得るので、埋め込み値が `'1'` のときも **ダイアログあり** と扱われる。

### 入室

1. **いったん保存 POST は送らない**。
2. `#addtend_dialog_mail` が開き、文言は **「保護者様に通知をしてもよろしいですか?」**（出席表 HTML 内のダイアログと一致）。
3. ユーザーが選ぶ:
   - **「通知する」** → `data_list.mail_flg = **1**` として `AttendanceSave`
   - **「通知しない」** → `data_list.mail_flg = **0**` として `AttendanceSave`
4. hidden（`#hidden_r_id` 等）に渡していた入室用パラメータと組み合わせて POST する。

### 退室

- 入室時間取得 API や 30分未満ダイアログ、算定区分モーダル、延長支援モーダルなど **既存フローを経た後**、退室用 `data_list` が完成する。
- その時点で **`is_mail == 1` なら** 同じ **保護者通知ダイアログ** を開き、`globalSendLeaveMailDataList` に退室用 `data_list` を保持する。
- ユーザーが「通知する / 通知しない」を選ぶと **その `mail_flg`（1 または 0）** を `data_list` に付けて `AttendanceSave`。

### ユーザー体感

- **必ず**（設定上）通知の意思確認が挟まる。  
- **`is_mail === 1` でも、ダイアログで「通知しない」を選べば POST の `mail_flg` は 0** になる。

---

## `mail_flg` **1** と **0** の違い（POST 上）

- フロントではどちらも同じ `ajax/ajax_attendance.php`（または保育時は `ajax_attendance_hoiku.php`）へ `data_list` ごと送信する。
- **違いは `data_list.mail_flg` の値だけ**（それ以外の入退室実績フィールドは同じ流れで送られる）。
- **実際にメールが飛ぶか・誰の宛先か**は PHP 側実装・DB の保護者メール設定次第。**保存済み HTML からは宛先や文面は読み取れない**。

`AttendanceSave` 成功時に `hidden_mail_only` など特別なレスポンスがあると、**実績は既に保存済みでメール確認だけ**といった分岐もある（ダイアログを閉じるだけ等）。

---

## まとめ表

| 設定 | 入室・退室まわりのフロントの結果 |
|------|----------------------------------|
| **`is_mail` が 0** | 通知ダイアログなし。入室時は `mail_flg` 固定 0 で即 POST。退室時も通知確認なしで POST（`mail_flg` 省略時はサーバ任せ）。 |
| **`is_mail` が 1** | **先に**「保護者様に通知を…」ダイアログ。ユーザーの選択で **`mail_flg` が 1 または 0** になり、その後 `AttendanceSave`。 |
| **POST の `mail_flg` が 0** | 「今回は通知しない」意思としてサーバへ渡る（サーバが送らない想定）。 |
| **POST の `mail_flg` が 1** | 「今回は通知する」意思としてサーバへ渡る（サーバが送る想定）。 |

---

## 参考（ソース上の分岐）

- **入室**: `sendEnterMail` … `is_mail == '1'` ならダイアログ、否则 `mail_flg: 0` で `AttendanceSave`。
- **通知ダイアログ確定**: `.send_mail_button` クリックで `data_list["mail_flg"] = $(this).data("send_mail")`（1 または 0）のあと `AttendanceSave`。
- **退室**: `setAttendanceSaveData` 内で `is_mail == 1` のとき `globalSendLeaveMailDataList` をセットして `#addtend_dialog_mail` を開く。`is_mail` が 1 でないときは `AttendanceSave` 直呼び。

以上は `attendance.js` のクライアント挙動の要約であり、メールの実送信・文言・宛先はサーバ（`ajax_attendance.php` 等）の仕様に依存します。
