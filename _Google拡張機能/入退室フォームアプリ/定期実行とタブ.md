# 定期実行とタブの関係

入退室フォームアプリ（`timer.js`）の自動更新が、複数タブでどう動くかを整理したメモ。

## 結論

**通常の使い方（1ウィンドウで wm タブを1つ表示）なら、気にしなくてよい。**

- データ取得（`fetch`）は **表示中のタブだけ** が実行する。
- バックグラウンドの wm タブはタイマーは動くが、`fetch` はスキップされる。
- 「全タブで1回にまとめる」ようなタブ間協調は **していない** が、表示タブ限定のガードで実質的な負荷は抑えられている。

## アーキテクチャ

| 項目 | 内容 |
|------|------|
| 実行場所 | content script（`manifest.json` の `content_scripts`） |
| background / Service Worker | **なし** |
| 対象 URL | `https://www.hug-ayumu.link/hug/wm/*`（`addition_plan.php` 除く） |
| 定期間隔 | `INTERVAL_MS` = 1分（`timer.js`） |

マッチする **タブごと** に `timer.js` が注入され、それぞれが独自の `setInterval` を持つ。タブ間でタイマーや取得結果を共有する仕組みはない。

## タブごとの動き

### 1. タイマー登録（タブごと）

`load` 時に各タブで:

1. 表示中なら即 `runAttendanceUpdate()` を1回
2. `setInterval` で `INTERVAL_MS` ごとに `runAttendanceUpdate()` を呼ぶ

非表示タブでも `setInterval` 自体は登録されたまま。

### 2. 実際の取得（表示タブのみ）

`shouldRunScheduledUpdate()` が `false` のときは `fetch` しない。

```text
スキップ条件:
  - document.hidden === true（タブが非表示）
  - isAutoUpdatePaused() === true（定義されていれば）
```

`isRunning` による二重起動防止は **同一タブ内のみ**。他タブとは無関係。

### 3. タブを再度表示したとき

`visibilitychange` で、前回の定期実行から `INTERVAL_MS` 以上経過していれば、そのタブで再取得する。

## 負荷の目安

| シナリオ | fetch の回数感 |
|----------|----------------|
| wm タブ1つだけ表示 | 約1分に1回 |
| wm タブを複数開くが1つだけ表示 | 表示タブのみ約1分に1回 |
| wm タブを切り替える | 表示したタブで、間隔を満たせば追加で1回ありうる |
| **別ウィンドウ**で wm を同時表示 | ウィンドウごとにそれぞれ定期 fetch（重複しうる） |

## 気にしなくてよいケース

- 同じブラウザウィンドウで、入退室ページを **1タブだけ前面表示** している
- 他の wm タブはバックグラウンドに置いている

→ 定期の `fetchAttendanceData` は実質 **前面タブだけ**。

## 注意した方がよいケース（稀）

- **複数ウィンドウ**で wm ページを同時に表示している → ウィンドウ数分、定期 fetch が走る
- タブ切り替えが頻繁で、かつ切り替えるたびに前回取得から1分以上空いている → 切り替え時に追加 fetch が入りうる

いずれも「タブ数 × 毎分」ではなく、**表示されている面の数**に近い。

## 関連ファイル

| ファイル | 役割 |
|----------|------|
| `timer.js` | `setInterval`、`shouldRunScheduledUpdate`、`runAttendanceUpdate` |
| `content.js` | `fetchAttendanceData`（HTTP 取得） |
| `form/form-render.js` | 取得結果のパネル描画 |

## 将来「絶対に1回だけ」にしたい場合

現状はタブ間協調なし。次のような追加が必要:

- `chrome.alarms` + Service Worker で1箇所だけ定期実行し、結果を `chrome.tabs.sendMessage` で配信
- または `BroadcastChannel` / `localStorage` + リーダータブ選出で、取得は1タブ・描画は各タブ

現時点の要件（表示タブだけ更新）では **必須ではない**。
